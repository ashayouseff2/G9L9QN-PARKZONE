# Prototype and validation
## Prototype screens
The Figma work includes location selection, area result, rules/payment, completion, unmatched-location and cannot-verify states, plus a large-screen area-result layout. The clickable flow includes start, zone result, payment details, place information, demo payment confirmation and location unavailable.

## Browser demonstration
Open [prototype/index.html](../../prototype/index.html). The browser prototype demonstrates a subset of the journey using illustrative content. The location field accepts typed text but does not geocode it. The payment action is a demonstration only.

## Feedback
Three participants reviewed the clickable prototype. Feedback was qualitatively positive overall, with some complexity and trust/source concerns. No formal time-on-task or per-person task-success measurements were captured.

## Next validation
- Recruit a broader range of drivers, including visitors unfamiliar with local language.
- Ask each participant to determine whether they may park in a given scenario.
- Record task success, time, wrong turns, help requests and confidence.
- Test unknown and permit-only scenarios explicitly.
- Verify zone, price, hour and restriction information against official sources before presenting it as current.
